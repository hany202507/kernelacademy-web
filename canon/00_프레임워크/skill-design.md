# 스킬 설계 · 공개 플러그인에서 무엇을 배우고 무엇을 보완하는가

updated: 2026-08-31 · renders: 책 2부 보론 / T2 S5 스튜디오 / YT "스킬 만들기 전에 정할 것"

## 0. 이 문서가 하는 일

Anthropic 이 공개한 Finance 플러그인(스킬 8개, 1,906줄)을 메종블룸 데이터키트에 세 번 돌려 채점했다. 그 실측에서 답할 질문은 셋이다.

1. **무엇을 자동화하는가** · 벤더가 자동화 대상으로 정의한 업무 목록
2. **자동화할 때 무엇을 고려하는가** · 돌려 보고 나온 설계 규칙
3. **내 업무와 비교해 무엇을 보완하는가** · 스킬이 못 덮는 것

실측 기록은 [courses/클로드아카데미](../../courses/클로드아카데미/).

## 1. 무엇을 자동화하는가

스킬 8개가 곧 벤더의 자동화 대상 목록이다. 우리 워크플로에 대면 이렇다.

| 스킬 | 자동화하는 업무 | 우리 워크플로 |
|---|---|---|
| reconciliation | GL·보조원장·은행·회사간 대사 | 회계결산 |
| journal-entry / -prep | 계상·상각·수익인식 분개와 검토 | 회계결산 |
| close-management | 결산 일정·선후관계·진척 관리 | 회계결산 |
| financial-statements | 재무제표 생성·기간 비교 | 보고 |
| variance-analysis | 증감 분해·중요성 판정·설명문 | 보고·예산관리 |
| audit-support / sox-testing | 표본 선정·조서·통제 평가 | 감사대응·내부통제 |

여기서 읽을 것 둘.

- **대사·분개·변동분석처럼 규칙이 분명한 반복 업무부터 자동화한다.** 벤더의 선택이 우리 6블록의 P·V 우선 순서와 같다
- **7워크플로 중 세무·자금이 목록에 없다.** 세무는 제도 종속이라 글로벌 스킬로 만들 수 없는 영역이고, 그래서 우리가 만든다

## 2. 자동화할 때 무엇을 고려하는가

돌려 보기 전에는 안 보이던 것들이다. 관찰 → 규칙 여덟.

| # | 실측에서 벌어진 일 | 규칙 |
|---|---|---|
| 1 | 계정과목 마스터 한 줄을 안 읽어 2.34억 총액 계상이 통과 | **정의 확인이 0단계.** 계정 정의·계약 조건을 읽는 단계를 맨 앞에 고정 |
| 2 | 총액 열끼리 맞추자 차이가 0으로 떨어져 수수료 9,084만원이 실종 | **비교할 열을 사람이 고정.** 필수 인자로 받고 기본값 금지 |
| 3 | 회계처리 판단 건이 「차이」로 뭉개짐 | **판정은 넷.** 통과 / 차이 / 보류 / **판단필요**(사람 회부) |
| 4 | 진짜 차이 0 집계 → 분개 0건, 공회전이 「이상 없음」으로 보임 | **차이 없음과 비교 실패를 구분해 표시** |
| 5 | 전기에도 같이 틀린 항목은 변동분석에서 정상 성장으로 보임 | **변하지 않은 것을 따로 점검** |
| 6 | ASC 606 다섯 단계를 적고도 본인·대리인 판단이 없음 | **기준서를 인용하면 판단 분기까지 나열.** 조문 이름만 적지 않는다 |
| 7 | 모델이 만든 표는 계산인지 생성인지 구분 불가 | **계산은 코드·수식, 스킬은 규칙과 양식, 판단은 사람** |
| 8 | 임계값이 달러 예시인 채로 실행됨 | **임계값을 채우기 전에는 실행되지 않게** |

여덟 규칙의 공통점이 있다. **전부 스킬을 만들 때 한 번 넣는 설계이지, 매 실행마다 사람이 하는 일이 아니다.** 설계에 사람이 들어가는 것과 실행이 자동인 것은 모순이 아니다. 잘못 설계하면 매달 자동으로 틀린다.

「판단필요」의 분량이 자동화의 품질 지표다. 실측에서 6건 중 판단필요는 1건이었다. 판단필요가 쌓이면 규칙이 덜 적힌 것이고, 같은 판단이 반복되면 규칙으로 승격해 줄인다. 판단필요는 줄어드는 방향으로 설계한다.

그리고 하나 더. **돌려 보기 전에는 완성이 아니다.** 골든셋(오류를 심은 데이터 + 정답표)으로 채점하고, 놓친 것을 규칙으로 승격한다. 인자 치환 결함처럼 문서 검토로는 절대 안 나오는 것이 있다.

## 3. 내 업무와 비교해 무엇을 보완하는가

스킬 1,906줄 전수 검색과 한국 거래 10건 실측으로 확인한 공백이다.

| 공백 | 실측 근거 | 보완 |
|---|---|---|
| **부가세** | 부가가치세·매입세액 0회. 불공제(접대비·승용차) 개념 없음 | 부가세 분리·불공제 판정을 국내 정본 스킬로 |
| **원천징수** | withholding 0회. payroll tax 는 사용자 부담분 구조 | 예수금 분개 구조를 국내 정본으로 |
| **계정체계** | Accrued liabilities 식 미국 계정. 더존 매핑 없음 | 계정과목 매핑 테이블을 스킬 인자로 |
| **신고 달력** | 결산 체크 40항목에 외부 신고 기한 0건 | 익월 10일(원천세·세금계산서)·25일(부가세)을 결산 달력에 |
| **총액/순액 판단** | principal·agent·gross·net 모두 0회 | 수익 인식 전 본인·대리인 확인 단계 |
| **ERP 연동** | "no supported MCP servers yet". 더존·이카운트는 언급도 없음 | 파일 반출 절차 또는 자체 커넥터 |
| **산출 양식** | 달러·천 단위·Dr/Cr | 원화·백만원·차변/대변 조서 양식 |

한 줄로 접으면, **방법론(대사 양식·결산 선후관계·임계값 산정)은 국경이 없어 가져다 쓰고, 제도(세목·계정·기한·판단)는 전부 우리 몫이다.** [원리 §4](principles.md)의 번역·연결·기록·확인이 스킬 단위에서 이렇게 나타난다.

## 4. 체크리스트 (스킬을 만들거나 들여올 때)

### C 연동
- [ ] 원본 시스템·파일 형식을 적었는가. 커넥터가 없으면 대체 경로는
- [ ] 정의 파일(계정과목 마스터·계약 조건·요율표) 경로를 인자로 받는가

### P 처리
- [ ] 비교할 열을 인자로 받는가. 기본값은 없는가
- [ ] 계산이 코드인가 모델인가. 산출물에서 구분되는가
- [ ] 예수금·부가세·원천징수 구조가 유형 목록에 있는가

### J 판단
- [ ] 사람 회부 조건이 금액·유형·경과일로 적혀 있는가
- [ ] 인용 기준서의 판단 분기가 나열돼 있는가
- [ ] 총액/순액·자산화/비용화를 자동 처리하지 않는가

### V 검증
- [ ] 이 스킬이 **구조적으로 못 잡는 오류**를 명시했는가
- [ ] 판정이 네 가지인가. 검증 세션이 분리되는가
- [ ] 전기와 동일하게 처리된 항목을 따로 내는가
- [ ] 골든셋 채점을 통과했는가

### D 산출
- [ ] 차이 0과 비교 실패가 구분되는가
- [ ] 임계값이 예시가 아니라 실제 값인가
- [ ] 통화·단위·차대변이 국내 조서 양식인가
- [ ] 확인하지 않은 것이 산출물에 적히는가
